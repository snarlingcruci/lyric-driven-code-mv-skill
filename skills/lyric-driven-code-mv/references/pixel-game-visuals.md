# 像素世界与演出

## 世界与身份

先定人物身份、轮廓、常用装束、两个所在地、共同意象与道具用途。用角色 ID 表示身份，服装只表示状态；通过发型、轮廓、章节标记和连续镜头保持可识别性。复用地图块、室内模块、精灵动作、HUD 和粒子，将时间预算放在动作及镜头上。

意象可成为角色能操作的物件：思念变成信件，真心变成收集后填满的心，保留变成物件上架，等待变成迟迟未满的进度，距离变成缺失的队伍成员或中断的路线。数值先有叙事意义，再决定样式和关键帧。

只需可观看演出时，菜单选择、碰撞、加分、失败和连接可按时间预排。显示“已连接”本身不需要网络服务。

## 网格与渲染层

建议从虚拟低分辨率开始，再整数放大；例如 `384×216 → 1920×1080` 为五倍，`320×180 → 1920×1080` 为六倍。两轴比例一致。角色、摄像机、遮罩边界尽量对齐虚拟像素。

```js
ctx.imageSmoothingEnabled = false;
ctx.drawImage(spriteSheet, sx, sy, sw, sh, Math.round(x), Math.round(y), sw, sh);
```

```css
canvas, .pixel-sprite { image-rendering: pixelated; }
```

精灵动作可以低于成片帧率，约 8–12 fps 是可选设计值。雪、烟、极光、波纹、镜头运动仍由成片时钟控制。`image-rendering` 不会自动将 DOM 中文字体变成像素字；字幕可以保持高分辨率清晰文字，需要全网格一致时再使用字形图集或低分辨率画布文字。

常用图层由后至前：远景→地图/房屋→道具与人物→氛围→HUD→字幕→跨屏/转场覆盖层。镜头移动作用于世界层，HUD 与字幕保持阅读位置。为角色遮挡、前景屋檐及字幕安全区单独检查图层顺序。

## 有意义的镜头变化

| 镜头 | 适用任务 |
|---|---|
| 侧视卷轴 | 跑、送、追及逐渐增长的距离 |
| 竖向跟随 | 攀升和难以触及的目标 |
| 俯视地图 | 路径、脚印、章节和关系的地理尺度 |
| 室内剖面/特写 | 等待、选择、保留与个人记忆 |
| 圆窗/相册/雪球 | 观察、回忆、梦与被保存的世界 |
| 双人分屏 | 两地人物及共同时间；跨屏线索兑现联系 |

让转场说明关系：相册收纳经历，梦窗扩大进入梦，存档世界缩入纪念物，望远镜改变观察尺度。棋盘揭露、阶梯擦屏和像素碎块重组可作为复用视觉效果，但需留出动作结果与文字的阅读时间。

双人分屏先建立两个所在地与各自行动，再把光锥、星链或肖像画到顶层跨过边界，最后给出进度完成。共同举灯发生在连接完成以后。两屏共用音乐时钟，分界位置也由时间求值。

## 视觉检查

检查首尾、每镜中点、关键动作峰值和转场前后：人物可辨、道具无突现、HUD 有原因、边缘不因缩放模糊、字幕不被遮挡。抽帧无法判断完整动作是否自然，最终以完整播放核对节奏、冷暖和留白。去掉字幕再观看一次，确认动作承担了歌曲含义。
